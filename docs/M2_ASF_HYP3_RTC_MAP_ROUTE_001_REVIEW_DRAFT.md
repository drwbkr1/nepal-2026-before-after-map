## What this would solve

The project has an editable EPSG:32645 ArcGIS metadata workspace, but no real before/after pair has passed usable-pixel and registration QA. The local ArcGIS radar GTC attempts are terminal without a valid projected pair, and the assessed optical pairs are blocked. ASF's HyP3 Basic can generate full-scene GAMMA RTC UTM GeoTIFFs from Sentinel-1 IW GRD-H scenes, including VV/VH and a layover/shadow raster. This is a **new processed source and method** that could supply inspectable ArcGIS map inputs; it cannot be labeled a successful continuation of the prior local processing. [Current map gap](M2_MAP_DELIVERABLE_GAP_001.md) · [ASF product guide](https://hyp3-docs.asf.alaska.edu/guides/rtc_product_guide/)

## Recommended exact route

The [draft proposal](../contracts/milestone-002-asf-hyp3-rtc-map-route-001-proposal-draft.json) names the same four source IDs as the frozen ascending radar pair plan: 16 August M1-SRC-001/002 before and 28 August M1-SRC-004/005 after. All four exact Sentinel-1D GRD names returned public ASF catalog rows. The event-area pair M1-SRC-002/005 had 100% *catalog* overlap of the source and upper-corridor AOIs, but only 96.999% of the overview AOI; the adjacent M1-SRC-001/004 pair covers a different roughly 2.994% overview strip. A [new union-by-date calculation](../records/observations/m2-asf-four-source-catalog-mosaic-coverage-001-local.json) places all four catalog footprints at **99.993% both-date overview overlap** and 100% for both event AOIs. This clears the frozen 99% threshold as a **catalog screen**, not as provider output or usable RTC pixels. [Pair triage](../records/observations/m2-radar-event-pair-catalog-triage-001.json) · [ASF observations](M2_ASF_HYP3_MAP_ROUTE_PREPARATION_001_LOCAL.md)

The [offline candidate](../records/observations/m2-asf-rtc-four-scene-candidate-001-local.json) proposes one 10 m `RTC_GAMMA` job per exact scene, in event-first order **002, 005, 001, 004**, with Copernicus DEM, gamma0 **power** output, no provider speckle filter or DEM matching, and the optional DEM/incidence/scattering-area files included. ASF's guide supports these option values and describes power as appropriate for statistics. Output dB would be derived for display only after a reviewed positive-value rule. This is separate from the earlier unapproved two-scene dB candidate. HyP3 GAMMA, its DEM and orbit use, and its mask codes must be recorded as their own provenance; the project's local AUX_RESORB files and `REFINED_LEE` cannot be claimed as used by ASF. [ASF guide](https://hyp3-docs.asf.alaska.edu/guides/rtc_product_guide/)

ASF lists **60 free Basic credits per 10 m RTC job**, so four successful jobs would nominally use **240 credits** if the owner's account has enough balance and the service accepts all four scenes. Basic documentation lists 8,000 monthly credits and a 14-day output retention period. No purchase is proposed. Actual account balance and job eligibility have not been checked. ## One conditional envelope, after the account decision

If later approved as an exact packet, this would cover separate implementation and synthetic ArcGIS tests, public CI, a fresh no-content gate, owner-controlled Earthdata access, up to one fixed job submission per scene, non-Git output custody and verification, real pixel and mask QA, and only on a target-AOI QA pass a **local** source-linked ArcGIS before/after visual panel. It would stop on account/terms/rights ambiguity, insufficient credits, a failed public gate, a rejected or failed job, unverifiable product identity, or failed or indeterminate pixel QA. The event pair would be evaluated before requesting the adjacent overview scenes. Each accepted job and its credit use would be retained even if later QA blocks. No automatic duplicate submission or paid credits are proposed. This limit is tied to public job visibility, credit consumption, and output retention, not an artificial expiry of the overall project goal.

The current [pixel QA contract](../config/qa/pixel-readiness-contract.json) still requires 99% coverage, 80% usable AOI area, compatible 10 m projected grids, and a passing stable-control registration test for `PASS_QA_ONLY`. ASF's layover/shadow file has to be mapped from the **actual product** README or metadata; OPERA RTC code values cannot be substituted. The map would display NoData and exclusions rather than filling them. ASF asks that publications and presentations include the acknowledgement supplied with each product; the package workflow must retain that product-specific text and its DOI metadata for eventual exports. The [change-evidence contract](../config/qa/change-evidence-contract.json) remains unopened for real M4 work: its four-source binding, fixed dB/robust-z thresholds, and separate route dispositions must not be silently transferred to a different provider. No baseline admission, change polygon, event attribution, derived-pixel publication, or final M6 package is approved by this draft.
