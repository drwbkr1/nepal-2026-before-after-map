# M2 Landsat-9 EarthExplorer local-download recovery-001 — local review

**Status: zero decision.** This packet proposes one conditional recovery envelope. Preparing it did not read either downloaded archive, click a download control, change custody, publish to Git, or run pixel QA.

## What happened

The approved first intake published its implementation and passed [public CI run 36612172656](https://github.com/drwbkr1/nepal-2026-before-after-map/actions/runs/36612172656). Its 10 August preflight passed. One exact EarthExplorer **Level-2 Product Bundle / Download Product** click opened two new tabs whose short-lived links used the USGS `landsatlook.usgs.gov` host. The browser event/path listener on the EarthExplorer tab timed out. Two exact-product-named files appeared in Downloads at nearly the same time, each **1,126,565,376 bytes** by filesystem metadata. No signed URL or account identifier was copied into project files. A prior tab-inventory tool result did expose the ephemeral signed URLs privately; the recovery must not repeat that output or replay a link. The files have not been opened or hashed. This is evidence of a handoff failure, not a verified archive or a second authorized click.

The original attempt `landsat9-before-20260810-001` is terminal. Its [reconciliation](../records/readiness/m2-landsat9-usgs-bundle-intake-001-terminal-reconciliation.json) and [post-CI record](../records/readiness/m2-landsat9-usgs-bundle-intake-001-post-ci-reconciliation.json) passed public terminal CI. The 26 August request never started. No Landsat archive entered controlled custody. The separate ASF HyP3 side-by-side ArcGIS panel remains a **partial, unregistered visual**; both full-area radar dispositions remain `defer`.

## Proposed single decision

Approve the [recovery proposal](../contracts/milestone-002-landsat9-local-download-recovery-001-proposal.json) as one conditional envelope. It would first implement and publicly test an exact-name Downloads handoff using disposable files. After fresh public CI and no-payload preflight, it would inspect the **two existing 10 August files once**, require their complete SHA-256 hashes to agree, reject any drift, unsafe path, or TAR/MTL identity failure, and promote only verified bytes into a **new append-only successor asset** by atomic no-replace operation. The prior terminal attempt remains unchanged, and neither browser original is removed.

Only if that before asset passes, the envelope permits **one** new owner-initiated click for the exact 26 August Level-2 bundle. A bounded local-file monitor would accept only one or two newly arrived exact-product names, require stable complete files and duplicate-byte agreement when two appear, then run the same container-only verifier and no-replace custody path. More than two outputs, missing or altered files, mismatched hashes, an account or terms change, or any ambiguity stops the sequence without a retry. Sanitized terminal publication and exact post-CI reconciliation are included in the same decision.

This changes the provenance method: a local filename and timing window replace the missing browser completion-path receipt. The extra duplicate-hash, stable-file, exact MTL, and safe TAR checks reduce risk, but **cannot supply an unpublished upstream checksum** or cryptographically prove that a local file came from USGS. The proposed pass would support local QA custody only. USGS identifies EarthExplorer as its Collection 2 download portal and describes the still-operational LandsatLook background service; those [USGS download instructions](https://www.usgs.gov/faqs/how-do-i-search-and-download-landsat-collection-2-data-products) and [service notice](https://landsatlook.usgs.gov/) establish the host relationship, not either file's integrity. The [risk screen](../records/readiness/m2-landsat9-local-download-recovery-001-risk-screen-local.json) records all eight source-gate dimensions and the current evidence limit.

The alternative is to leave the two files unadopted and design a fresh before acquisition with a different event-capture mechanism. That would need a separate reviewed method and at least one more before download; it is not released by this packet.

**Excluded:** any click for 10 August, replay of a signed link, token or terms action, source/date substitution, automatic retry, mutation of the first attempt, deletion of downloads, TIFF/header/pixel inspection, registration, AOI masks, change analysis, attribution, new ArcGIS raster map, derived-pixel publication, and scientific publication. A successful container intake would still require a separately reviewed Landsat pixel and map method.
