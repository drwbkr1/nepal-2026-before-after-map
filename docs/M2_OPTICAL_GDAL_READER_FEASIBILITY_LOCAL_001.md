# GDAL-only optical reader feasibility

**Status:** Local method research, not a source decision, production reader, reviewed method change, or real-data approval. The [disposable observation](../records/observations/m2-optical-gdal-reader-feasibility-local-001.json) and [repeatable script](../scripts/validate_m2_optical_gdal_reader_disposable_001.py) use only generated rasters.

The acquired M2-OPT-001/002 pair is still scientifically unassessed. Its one approved header recovery stopped after `arcpy-import-started`, before any header or pixel receipt. Two separate disposable ArcPy imports later passed but did not explain that exit. An ArcPy-independent reader could remove that import dependency from a **new** attempt, but it would be a method amendment requiring its own review. [Terminal reconciliation](../records/readiness/m2-optical-pair-header-receipt-recovery-001-post-ci-reconciliation.json)

The installed GDAL 3.12.2e opens generated JP2 files through `JP2KAK` by default and can be forced to use `JP2OpenJPEG`. On eight generated Sentinel-style raster roles, a GDAL metadata adapter supplied the unchanged optical header contract with dimensions, bands, pixel types, extent, cell size, and a CRS verified equivalent to EPSG:32645. The frozen pair predicate passed matching grids and blocked a deliberately shifted one. The reopened synthetic JP2s lacked an embedded EPSG authority code, so a future adapter must prove CRS equivalence explicitly instead of treating a missing authority code as either a pass or a different CRS.

The three-band quality-mask fixture exposed a test hazard: `REVERSIBLE=YES` alone, with the writer's default quality, lost an isolated mask value of 1. The final fixture used `REVERSIBLE=YES`, `QUALITY=100`, and `YCC=NO`, verified exact samples with both installed JP2 readers, then confirmed exact nearest-neighbor 60 m to 20 m mask behavior. The earlier failures and Windows handle-cleanup errors are retained in the observation. They do not show that actual Sentinel masks lose values; no acquired product was opened.

A second [source-free production-grid check](../records/observations/m2-optical-gdal-production-grid-local-001.json) wrote three generated 60 m mask bands to a disposable 1,576 × 1,317 JP2. The installed `JP2KAK` reader reopened it and resampled it to the frozen 4,726 × 3,950 cell, 20 m EPSG:32645 output grid. The result had the exact target transform and dimensions; all nonzero locations and class values matched independently calculated nearest-neighbor locations, including a partial edge cell. This synthetic, sparse JP2 does not establish real-product decoding cost, memory headroom, mask semantics, AOI coverage, or a usable optical pair.

Before any real optical route is proposed, a new implementation would still need exact source/member identity checks, all frozen header predicates, source-specific scaling metadata, actual-product JP2 I/O and memory bounds, AOI classification equivalence, mask semantics, stable registration, append-only safe receipts, synthetic failure tests, and ArcGIS export compatibility. A disposable pass cannot establish real cloud, shadow, snow, coverage, registration, or change. A separate reviewed authority and public gates would be required before another real process. The original and recovery attempts remain terminal and immutable.
