# Optical fallback catalog geometry screen (local, metadata only)

**Superseded status labels:** This original screen omitted the separately tested 12 August / 27 August M1 pair when labeling `NOT_TESTED`. Its geometry calculations remain valid, but its six-per-window untested count and prior-QA attributes are incomplete. Use the [corrected screen](M2_OPTICAL_FALLBACK_CATALOG_SCREEN_CORRECTION_002.md) for candidate status.

This local screen uses the already published CDSE Sentinel-2 L2A catalog snapshot and the approved AOIs. It projects the catalog footprints into EPSG:32645 and puts all 29 event-AOI-intersecting records in an ArcGIS-openable GeoPackage. The same-machine ArcGIS Pro 3.7.1 check imported the GeoPackage into a File GDB, saved an editable APRX, exported a PNG, and reopened the APRX in a fresh process with zero broken layers and a byte-identical export. The [local receipt](../records/observations/m2-optical-fallback-catalog-screen-local-001.json) binds the files and checks.

The earlier catalog review counted **14 before** and **15 after** footprints that *intersect* both event AOIs. Projected area intersection is more discriminating: only **7 before** and **7 after** cover at least 99% of *both* AOIs by footprint. The exact already tested 24 August / 16 September pair is in that full-footprint group but remains pixel-QA **BLOCK**. Six other records in each window have full-footprint geometry but have not been pixel-tested.

The two after-date examples in the map show why tile-level cloud cover is an unsafe shortcut. The 18 September record has 53.71% catalog tile cloud but covers only 40.41% of the upper-corridor AOI by footprint; the 21 September record has 60.28% tile cloud and covers 100% by footprint. Neither record is adopted, acquired, or known to have usable pixels in either AOI. Footprint coverage is a necessary geometry screen, not clear-pixel or registration evidence.
